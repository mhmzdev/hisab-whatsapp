# feat: Show connected tenant status and revoke hosted access          ✅ COMPLETED — 2026-09-13

## Problem

[#5](https://github.com/mhmzdev/hisab-whatsapp/issues/5) is the last child of [#1](https://github.com/mhmzdev/hisab-whatsapp/issues/1) with code in it. After #7 (PR #20) a tenant connects, but the Connected screen still shows mock rows for activity, entries, language and quota (`landing/app/portal/page.jsx:300-303`, `landing/content/mock.js` `CONNECTED`), the Revoke button is inert (`page.jsx:406-407`), and nothing anywhere deletes a ciphertext, stops a worker on request, or expires an inactive ledger. Spec 001 ("Revoke, quota, and money") fixes the contract: revoke stops the worker immediately and deletes the encrypted key; the ledger folder is retained inactive for 30 days; users export before revoking; the browser never sees ledger contents.

Blocked by #7, which is merging as PR #20; this branch is based on its tip.

## Approach

**The runner reads files, the worker learns nothing.** Every number the Connected screen shows already exists on disk in the tenant's state dir or vault, written by code that is not changing: the last inbound is the last `"dir": "in"` record in `data/<uid>/messages.jsonl` (`hisab/store.py:83-90`); this month's model calls are `data/<uid>/usage.json` (`store.py:67-80`); the language is `vault/<uid>/settings.json` (`hisab/ledger.py:41-56`); entries this month are the `n:` lines dated this month in the current quarter file (`ledger.py:58-68`, `:77-83`, one entry per `YYYY-MM-DD … ; n:N` line, and undo removes the block at `:113-131`, so a line count is exact). A new `runner/activity.py` computes `{lastSeenAt, entriesThisMonth, language, usedThisMonth, quotaLimit}` for connected tenants from those four files, and `main.py`'s tick writes the dict to the tenant document **only when it differs from what the snapshot already holds**. `reconcile.py:2-3` already excludes volatile fields from the state hash, so these writes never bounce a worker. This is the same shape as `runner/verify.py`: file-based, per tenant, no Firebase in `hisab/`. Reads are gated on file mtimes, so an idle tenant costs four `stat` calls per pass.

**Revoke is a client request and a runner transition.** The browser can never write `status` (`firestore.rules:14-21`), and that stays true. The client gains one more field, `revokeRequestedAt`, in `clientFields()`; the Connected screen's confirm button writes it. The runner's tick sees it on any running or errored document and runs `revoke()` in `runner/lifecycle.py`: stop the worker and **wait for it to exit** (`workers.py:27-30` gains a bounded wait then kill, so the vault is never moved under a live process), move `vault/<uid>` and `data/<uid>` to `inactive_root/<uid>/<revokedAt>/` with a `revoked.json` marker, delete `tenants_dir/<uid>`, then write `status: "revoked"`, `revokedAt`, and delete `keyCiphertext`, `creatorId`, `nonce`, `nonceExpiresAt`, `connectedAt`, `revokeRequestedAt`, the activity fields and `lastError*`. `agentName` and `createdAt` stay so the Revoked screen can name what was revoked. The order (stop → move → write) makes a crash between steps safe: `revokeRequestedAt` is still set on the next tick, the move is skipped if the source is gone, and the write is repeated. "Immediately" means within one 2-second tick plus the worker's exit.

**Retention is a sweep, not a job.** `runner/lifecycle.py` also has `sweep_inactive()`: delete every `inactive_root/<uid>/<ts>/` whose `revoked.json` is older than `retention_days` (runner config, default 30). It only ever removes a directory that carries the marker, directly under `inactive_root`, so a stray folder is never touched. Runs once at startup and then at most hourly from the tick. Reconnecting after revoke is a **new tenant on the same uid**: `admission()` (`reconcile.py:50-61`) re-admits a `revoked` document that carries a decryptable ciphertext, `vault/<uid>` no longer exists, and the worker runs setup from zero. That is the reading of "cannot resume from it without a new connection" that matches the shipped portal copy (`portal_revoked_muted`: "Reconnecting starts a new ledger. The old one is not merged."). The retained copy exists for the operator to hand back on request during the 30 days, nothing more.

**The portal renders, it does not compute.** `ConnectedState` reads the five new fields from the live snapshot it already subscribes to (`page.jsx:395-404`); relative time comes from `Intl.RelativeTimeFormat` in the page language (`ur` has a locale; `roman` uses `en`); the language row maps `en`/`ur`/`roman` to three new strings; the quota bar is `usedThisMonth / quotaLimit`; the plan row keeps its presentation string (plan tiers are out of scope by spec). While `revokeRequestedAt` is set and `status` is not yet `revoked`, the confirm box is replaced by a "Revoking…" line so a double-click cannot double-write. `RevokedState`'s "Connect an agent" button sets a UI phase that renders `ConnectState`; the next snapshot with `status: pending` (runner admission) clears it. The export-before-revoke message already exists in `portal_connected_revoke_confirm_text` and the export hint above the button; no copy changes there.

**Invariants kept.** Six tools: nothing in `hisab/` changes except nothing at all — the worker is stopped from outside. Strict check, entry numbers, undo, dedup, offset-after-batch: untouched. Three languages: five new keys in `landing/content/strings.json` in `en`/`ur`/`roman`, enforced by `tests/check_landing.py`. Privacy: the activity fields are counts, a timestamp and a language code, never a description or an amount; fixtures use fake uids and the `demo-*` project; the moved vault stays on the runner's disk and is never written to Firestore.

## Risks

- **A revoke while the worker is mid-turn.** `terminate()` lands between a model reply and the store write; the reply may still go out, and the vault move waits for exit (bounded 10 s, then kill). Accepted: the ledger is moved intact either way, and the user asked for the stop.
- **`inactive_root` is under the compose mount.** `runner-data/` is bind-mounted, so moves are same-filesystem renames. If an operator points `inactive_root` elsewhere, `shutil.move` copies; still correct, just slower.
- **Relative-time locale.** `Intl.RelativeTimeFormat('ur')` renders Urdu digits and words in current Chrome and Safari; an old WebView falls back to `en`. The row is informational.
- **Activity pass cost.** Four `stat` calls per connected tenant every 10 s, a file read only when an mtime moved. At hundreds of tenants this is still trivial; if it ever matters, the worker could touch one sentinel file.
- **`#22` may remove Roman Urdu from `landing/` in parallel.** This branch adds strings in all three; whichever merges second resolves a trivial `strings.json` conflict.

## Out of scope

- Plan tiers, `maxAgents`, payment confirmation, and any pricing logic (spec 001 "Revoke, quota, and money").
- Restoring a retained ledger to a reconnected tenant (operator action on request; the retained copy is for that).
- A uniqueness check on the decrypted token across tenants (#7 risks list).
- Syncing activity for `pending` tenants (they have no ledger yet; the Check screen has nothing to show).
- Changing the quota counting point or the 80% warning (#6).
